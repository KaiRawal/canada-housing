## Standing decisions

- Target formulation (level vs Δlog vs YoY): **LEVEL — decided empirically in T2.2** (Δlog and YoY% give no directional gain and worse point errors; see T2.2 learning below)
- Validation scheme: expanding-window CV over years, grouped by CMA (defined once in harness.py, T1)
- Metrics: MDA, NMSE, NRMSE, NMAE (reuse evaluation/evaluation.py); persistence baseline always reported alongside
- Registry discipline: runs.jsonl is STRICTLY APPEND-ONLY (duplicates kept, superseded rows never deleted); duplicate run_ids ARE possible under append-only — downstream tooling MUST dedupe by (run_id, timestamp)
- Registry hygiene (T4.1 critic fix #5) — THREE KNOWN SUPERSEDED-ROW TRAP PATTERNS when consuming runs.jsonl: (a) DIFFERING-ID DRAFT PAIRS: the same logical experiment logged under two different ids across a fix (e.g. T3.2's "…all blocks-vs-lag1only" vs the corrected "…all-blocks-vs-lag1only"); ids alone do not identify a logical run. (b) DUPLICATE-ID SMOKE/REGENERATION ROWS: identical ids re-appended on regeneration sweeps (e.g. T1.1-harness-smoke, all T3.2 rows ×3) — keep the LATEST timestamp. (c) BROKEN-THEN-FIXED-ID rows: an early draft of a run_id carries metrics from a pre-bugfix code path and later same-id rows supersede it (e.g. T4.1's first-sweep enet rows came from a non-converging raw-target ElasticNet before the y-standardization fix; latest-timestamp rows are authoritative). ALWAYS dedupe keeping latest (run_id, timestamp) AND cross-check analyses/T<stage>.<sub>.md when ids differ across drafts of one logical experiment.
- Canonical MDA protocol: harness.mda_zero_drop (boundary-anchored, symmetric zero-direction drop); canonical persistence reference = MDA 0.6771±0.0474 / NMSE 1.52e-06±1.27e-06 / NRMSE 0.00113±0.00049 / NMAE 0.00061±0.00024; paired sensitivity via harness.paired_intersection_scores
- Multi-metric bar (T3.2 critic fix #2, EXPLICIT; codified T4.4 gate 2026-08-28): a directional edge alone never constitutes "better" — a model only counts as beating persistence if it wins on MDA AND does not degrade the point-error class materially (>10% worse NRMSE disqualifies, denominator = global-best NRMSE across all T4 combos, currently B-enet 0.00107 thresh 0.00118); per-fold signs of any claimed edge must be reported honestly. Adjudicated: A-enet 0.6490 is directional best (ΔMDA -0.0017 vs pers, 1/5 folds) but ineligible under this gate (1.109× global-best, would be 1.052× vs persistence 0.00113 and thus eligible under persistence-relative gate).
- Covariate timing convention (T3.3 critic fix #3): SCSS/RMS/Census covariate t−1 values are used AS IF available at month t; in reality SCSS/RMS publish with a delay and Census is annual — any REAL-TIME predictability claim built on these covariates must carry this caveat through T6/T8
- Upstream imputation panels stay canonical (T3.3 hard gate): the train-only re-imputation sensitivity quantified joint train+test imputation optimism as NEGLIGIBLE for the reference vehicles (|ΔNRMSE| ≤ 0.8% relative, |ΔMDA| ≤ 0.001, persistence reproduced exactly) → T4+ keep the joint-imputation X_train panel for comparability with all T1–T3 references and carry the ≤~1% caveat; alternative panel committed at artifacts/T3.3/X_train_trainonly_total.csv.gz
- Success criterion (roadmap amendment 2026-08-28): primary goal = NRMSE -20% vs persistence (0.00113→0.00090); 5% already achieved by B-enet 0.00107, remaining ~15% via T5 tuning + T4.3 recursive + ensemble is plausible. MDA +20% (0.677→0.812, +0.135) is implausible on monthly direction — near-martingale + 40% flats, best observed 0.649 still -0.028 short and no family trends upward — so MDA is reported honestly but not required for "beating" on the primary goal.
- Pruned feature scope for T5/T6 (2026-08-28): T5/T6 search only A_base_lag1 and B_base_lag1_OWN-subset (tot_d12/lag12/24/dlog1); C/k5 already C≈B under tuning, SCSS/RMS/k3 dropped per T3.3/T4.1 — keeps search to ~10 dims.
