**Inner-CV discipline identical to T4.1**: expanding time-ordered blocks WITHIN each outer train window ONLY (last 4×12 train months as successive inner val sets, training strictly earlier calendar months, pooled across CMAs, no shuffle). ## Decision rule & verdict

Pre-stated rule: winner = best mean MDA subject to mean NRMSE not >10% worse than best mean NRMSE across all T4.2 combos (same rule as T4.1).

- Best NRMSE among T4.2 combos = 0.001276 (RF-B) → threshold 0.001403.
- Eligible: RF-A/B/C, LGBM-B/C, XGB-B/C, LGBM-B/C-deep (9 combos).
- Highest MDA among eligible = **RF-A 0.6151** → **winner = RF-A (RandomForest on A_base_lag1)**.
- Tied-within-1e-4 set is {RF-A} alone.

**Honest signs:** even the winner loses to persistence on 4/5 folds (paired ΔMDA −0.0188), to B-enet on 4/5, and to ridge on 4/5. No tree combo beats persistence direction, and none beats B-enet's point-error class either (all ΔNRMSE vs persistence positive, i.e. worse).

**Breadth vs depth:** depth phase (LGBM-deep) did not improve breadth: LGBM-A-deep 0.5988 vs LGBM-A 0.5813 (+0.0175 but still below RF-A) and LGBM-B/C-deep slightly worse than their breadth counterparts. Winning GBM family LGBM was chosen by breadth MDA; deeper tuning (larger `n_estimators`, finer `learning_rate`) added no directional skill.

**Feature-set effect:** consistent with T4.1, B/C (OWN/nbr5) do not improve tree MDA over A — RF-A is best, and LGBM-C (0.5964) ≈ LGBM-A (0.5813) within noise. Trees do not exploit the OWN block the way linear ElasticNet did.

## Interpretation

1. **Non-linearity does not beat the linear ceiling here.** Every tree ensemble loses to persistence MDA 0.6771 by ~0.06–0.14 and to the linear B-enet winner on both metrics. The NHPI `total` panel at monthly frequency remains near-martingale — past levels predict next month's level better directionally than any non-linear function of 176 lag-1 covariates + engineered memory learned on ~5.6–7.3k rows.

2. **RandomForest (shallow, 30 trees) is the least-worst tree** but its 0.6151 MDA still trails A-enet's 0.6490 linear best and is not persistence-class on point errors (NRMSE 0.00135 vs 0.00113). Bagging helps slightly over boosting here; gradient boosters overfit the small panel (CAT catastrophically so on B/C: NRMSE 0.005–0.006, 5× persistence).

3. **Depth tuning is not a lever.** Doubling `n_estimators` and tuning `learning_rate`/`num_leaves` moved MDA by <0.02 and never crossed the eligibility frontier. This supports stopping tree tuning here and moving to T4.3 (temporal GBM / SARIMAX) or straight to T4.4 leaderboard with linear B-enet as frontrunner.

4. **Family ranking for T4.4:** linear B-enet (0.5981/0.00107) remains ahead of the best tree (RF-A 0.6151/0.00135) on point-error class despite RF-A's nominal +0.017 MDA edge — but RF-A's NRMSE is 26% worse than B-enet and 19% worse than persistence, so under the multi-metric bar (direction + point-error class) B-enet is still the T4 leader. Trees survive only as an ablation proof that non-linearity is not earned here.

## Pitfalls encountered

- **RF inner CV cost:** 100-tree RF with 4×12-month inner splits ≈118 s per outer fold inner CV; cut to 30 trees and 2-combo grid to meet bounded compute (~few minutes per fold after fix). Manual inner loop (clone + sequential fits) replaced `GridSearchCV(n_jobs=-1)` to avoid macOS `joblib` resource_tracker deadlocks / leaked semlocks observed in the first breadth sweep.

- **Reference B-enet inner nesting:** building a tuned B-enet reference with its own GridSearch inside each outer fold would double runtime; switched to a fixed representative (`alpha=0.001,l1_ratio=0.95`, median T4.1 winner) — explicit caveat in code.

- **B-enet proxy fidelity:** fixed proxy is within 0.003 MDA of the tuned B-enet aggregate; paired ΔMDA vs B-enet should be read as vs a strong linear proxy, not vs the per-fold tuned optimum. The ridge-a1 and persistence references are exact.

- **CatBoost on small panel:** with `depth 6` and `iterations 200` it overfits dramatically on B/C (fold-5 NRMSE blow-up). Depth tuning did not rescue it; keep CatBoost as "tried, failed" for the report.

- **Registry integrity (T4.2 critic fix #2):** `git diff 0d9c7fc..80aebf5 -- runs.jsonl` showed 26 `+{` lines not 21, due to superseded retries. Superseded/draft IDs enumerated: `T4.1-*` had 3 duplicates each (original + 2 re- appends), `T4.2-RF-A` logged 4× (MDA 0.5997/0.5997/0.6071/0.6150) with differing-ID pair `T4.2-rf-A` (lowercase, 1×) — leaderboard uses latest timestamp `2026-08-28T04:15:10` RF-A and dedupe rule (latest `(run_id, timestamp)`) per KNOWLEDGE.md trap (a). Also `T4.2-RF-B` 2×. All superseded rows remain in the file (append-only) but are ignored by analyses (see `decision_rule.json:skipped`).

- **Bounded-search caveat (T4.2 critic fix #3):** "no tree beats linear ceiling" is conditional on modest breadth (RF 2 combos 30 trees, GBMs 4 combos each, LGBM-deep 4 combos). Wider/deeper search was not run — add explicit caveat for T4.4 consumers (see `decision_rule.json:caveats` bounded-search note). Library versions recorded in `runs.jsonl:config.versions` for each new row (sklearn 1.9.0, lightgbm 4.7.0, xgboost 3.4.1, catboost 1.2.10).

- **Tree CV docstring (T4.2 critic fix #4):** tree pipelines contain only `("model",...)` with no scaler — documented as "no-op scaler for trees" (trees are scale-invariant, no y-standardization needed), consistent with harness discipline; not a leakage omission.
