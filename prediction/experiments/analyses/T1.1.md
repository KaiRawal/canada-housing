# T1.1 — CV harness (`prediction/experiments/harness.py`)

**Date:** 2026-08-26 · **Commit stage:** `exp(T1.1)` · **Run logged:** `T1.1-harness-smoke` (runs.jsonl)

## What was built

Single source of truth for all later experiments:

- **Data loading** — `load_train_data()` merges `prediction/X_train_full_total.csv`
  (row-aligned by position) with the ids/target in `prediction/y_train_full_total.csv`.
  Train split ONLY; the test files are never referenced anywhere in `experiments/`.
  Because the imputation CSVs include the held-out test splits, they were added to
  `.gitignore` (`prediction/*.csv`) — regenerate with `python imputation/data_imputation.py`.
- **Fold construction** — `build_folds()` (see design below), with per-fold row/CMA counts
  and assertions of strict temporal ordering.
- **Metrics** — thin wrappers around `evaluation/evaluation.py`: `calculate_all_metrics`
  for NMSE/NRMSE/NMAE, `mean_directional_accuracy_grouped` for a boundary-anchored MDA
  (see gotcha #1). No metric is reimplemented.
- **Baseline** — `persistence_predict()`: ŷ_t = y_{t−1} within CMA on the concatenated
  train+val window, so the first validation month uses the last train observation
  (past info only).
- **Runner** — `evaluate(model_fn, df, folds)`. Contract:
  `model_fn(train_features_with_ids, train_y) -> predict_fn(val_X) -> Series`.
  Model and baseline are scored on the SAME rows: only rows where truth, model pred,
  AND baseline pred are all present.
- **Logging** — `log_run()` appends one JSON line to `prediction/experiments/runs.jsonl`
  (schema = union of plan schema and registry convention, incl. `git_sha`, ISO timestamp).

## Fold design (FIXED from here on)

Expanding-window over calendar years, grouped by CMA. Validation windows are five
consecutive 2-year blocks ending at an **anchor year**: the last year in which ≥50% of
CMAs still have observations. On this dataset that anchor is **2017** (all 24 CMAs have
2017 rows; from 2019 onward only Sherbrooke remains — naive anchoring at the global max
year 2022 produced two degenerate 1-CMA folds, caught by the smoke test).

| Fold | Train years | Train rows / CMAs | Val years | Val rows / CMAs |
|---|---|---|---|---|
| 1 | <2008 | 5624 / 18 | 2008–09 | 432 / 18 |
| 2 | <2010 | 6056 / 18 | 2010–11 | 432 / 18 |
| 3 | <2012 | 6488 / 18 | 2012–13 | 432 / 18 |
| 4 | <2014 | 6920 / 18 | 2014–15 | 432 / 18 |
| 5 | <2016 | 7352 / 18 | 2016–17 | 323 / 24 |

Late-starting CMAs (Guelph, Kelowna, Oshawa, Ottawa-Gatineau-QC, Trois-Rivières start
2016-12; Sherbrooke runs to 2022-03) contribute only where they have rows; folds simply
skip them elsewhere.

## Smoke test results (frozen last-value model vs persistence)

The smoke model predicts each CMA's last *train* value for every validation month (it
cannot update within the window); persistence updates monthly. This is an infrastructure
check, not a formal baseline result (that is T1.2/T2.1).

| Aggregate (mean ± std across 5 folds) | MDA | NMSE | NRMSE | NMAE |
|---|---|---|---|---|
| Frozen last-value (model) | 0.387 ± 0.023 | 8.0e-05 ± 8.9e-05 | 0.0080 ± 0.0043 | 0.0057 ± 0.0028 |
| Persistence (baseline) | **0.459 ± 0.034** | **~3e-07** | **0.0012 ± 0.0005** | **0.0007 ± 0.0003** |

Persistence dominates the frozen variant on every fold — expected, and it confirms the
harness distinguishes predictors that use recent information from those that don't.

## Gotchas discovered

1. **MDA boundary loss.** `mean_directional_accuracy_grouped` diffs within CMA, so the
   first validation month's direction would be silently lost if metrics ran on val rows
   alone. Fix: each CMA's series is anchored with its last train observation
   (true=pred=last train value → zero error, NaN diff dropped) before calling the
   evaluation.py function. NMSE/NRMSE/NMAE stay unanchored.
2. **evaluation.py normalization quirk.** NMSE = MSE/n², NRMSE = RMSE/n, NMAE = MAE/n
   with n = number of scored rows (not a scale factor). Unusual but consistent across
   model/baseline/folds — comparisons remain valid; absolute values are not "fraction of
   variance" style numbers.
3. **Row alignment.** X/y train CSVs align positionally (imputation resets indices before
   export); harness asserts equal length then concatenates positionally.
4. **Upstream lag imputation caveat.** Feature lags are ffilled **and bfilled** within
   CMA inside the train split, so the first observation(s) of a CMA carry back-filled
   values. Minor, pre-existing, worth remembering during the T3.3 leakage audit.

## Sample sizes

Train split: 7792 rows × 176 features (+ ids + target), 24 CMAs, monthly 1981-01 →
2022-03. Long-history CMAs end 2017-01; Charlottetown 1995→2018-11; six late CMAs start
2016-12. No CMAs or rows were dropped by the harness itself.
