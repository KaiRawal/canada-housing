# T1.2 — Harness validation via persistence-baseline reproduction

**Date:** 2026-08-26 · **Commit stage:** `exp(T1.2)` · **Run logged:** `T1.2-baseline-validation` (runs.jsonl)

## What was done

`prediction/experiments/validate_baseline.py` runs the persistence predictor
through the harness (`harness.py`, unchanged logic) on all 5 expanding folds and
performs four groups of checks:

1. **Run A — exact smoke reproduction:** re-runs `evaluate(last_value_model_fn)`
   (identical configuration to T1.1) so the persistence baseline is scored on the
   identical folds AND identical row sets as the smoke test, then compares every
   per-fold baseline metric against `artifacts/T1.1/smoke_test_results.json`.
2. **Run B — canonical persistence reference:** scores persistence as BOTH model
   and baseline (`_score_fold` with `model_pred == baseline_pred`), giving the
   reference numbers all later models are judged against on persistence's own
   maximal evaluation set.
3. **Cross-check vs `prediction/prediction.py`:** recomputes persistence exactly
   the way `prediction.py` does — a global `groupby('cma_canonical').shift(1)`
   over the whole sorted train split — merges it onto the harness frame, and
   compares element-wise with the harness's fold-local concatenated shift on
   **every scored row of every fold**: 0 mismatches. This verifies the
   train→validation boundary month is handled identically (first val month
   predicted from the last train observation = past information only).
4. **Sanity checks (all asserted in-script):**
   - no NaN truths or predictions ever enter a scored set;
   - train strictly precedes validation globally AND per CMA in all 5 folds;
   - eval-row attrition accounts for every val row exactly
     (`n_val_rows = n_eval + dropped_truth_NaN + dropped_baseline_NaN`).

No test-split files were read at any point.

All per-fold baseline metrics equal `artifacts/T1.1/smoke_test_results.json`

### Fold-5 attrition, corrected (critic fix #2)

The T1.1 critic described fold 5 as "323→245 scored rows dropped from
late-starter CMAs". The precise accounting is:

| Source of row loss (fold 5) | Rows |
|---|---|
| Truth NaN | 0 |
| Persistence pred NaN (each CMA's first-ever observation falls in-window) | **6** |
| → persistence-as-model eval rows (Run B, canonical) | **317** |
| Further excluded because the *frozen last-value* model has no train rows for the 6 late-starter CMAs (common-mask effect in Run A / smoke) | 72 |
| → smoke-run eval rows | **245** |

The 6 dropped-by-baseline rows are the first observations (all 2016-12) of
Guelph, Kelowna, Oshawa, Ottawa-Gatineau (QC part), Sherbrooke and Trois-Rivières.
The additional 72-row gap between 317 and 245 exists only under Run A's scoring
protocol, where a model that cannot predict late-starter CMAs shrinks the common
evaluation set for BOTH predictors. **Warning:** do NOT read cross-fold metric
trends causally — folds differ in calendar period, CMA composition (18 vs 24),
and (under model-dependent common masks) evaluation-row sets; per-fold numbers
are paired comparisons within a fold only, never a time series of skill.

## Leakage assessment

- **Harness itself:** clean. Only `X_train_full_total.csv` / `y_train_full_total.csv`
  are loaded; fitting sees strictly pre-validation rows per fold; persistence uses
  `shift(1)` within CMA over train∪val (past-only); metrics are computed on
  identical row sets for model and baseline. Test files are never referenced.
- **[major caveat, inherited] Upstream imputation leakage:** `imputation/data_imputation.py`
  (lines ~458–467, the `impute_full_pipeline(temp_df, ...)` block) runs imputation
  on train+test **jointly** before the temporal split. Two concrete leak paths:
  (a) annual→monthly distribution of census anchors can distribute using the full
  panel including test-period years; (b) `yearly.interpolate(limit_direction="both")`
  back-fills early-period gaps with later (possibly test-period) values, so some
  train rows carry information from beyond the split. Consequence: CV absolutes
  may be mildly optimistic for imputed feature columns (the `total` target column
  itself comes from raw index data, but its lag features ride the same pipeline).
  **Scheduled mitigation:** train-only re-imputation sensitivity check in T3.3
  (or before T8) — re-run the imputation restricted to the train split, re-score
  the winning model, and report any val→val' degradation.

## Pitfalls encountered

- The `model_fn` contract deliberately hides validation targets from models, so a
  legitimate persistence *model* cannot be expressed through it (persistence needs
  y_{t−1} from inside the validation window). Hence Run B calls `_score_fold`
  directly with `model_pred == baseline_pred`; this is scoring-machinery reuse,
  not a bypass — Run A confirms the same machinery reproduces the smoke numbers.
- Fold-5 eval-set size is protocol-dependent (245 under a frozen-value companion
  model, 317 under persistence-as-model). Any future claim of "beating
  persistence" must compare on the SAME common mask, which `_score_fold`
  guarantees by construction.

## Sample sizes / fold dates

Train split: 7792 rows × 176 features (+ ids + target), 24 CMAs, monthly
1981-01 → 2022-03. Folds: val windows 2008-09, 2010-11, 2012-13, 2014-15,
2016-17; anchor year 2017. Folds 1–4: 18 CMAs / 432 val rows each, zero attrition.
Fold 5: 24 CMAs / 323 val rows → 317 scored (canonical) / 245 scored (smoke
protocol). No CMAs or rows were dropped by the harness itself.
