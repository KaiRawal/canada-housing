# T2.1 — Baseline suite under the harness: what is the real bar?

**Date:** 2026-08-26 · **Commit stage:** `exp(T2.1)` · **Runs logged:** `T2.1-drift`, `T2.1-arima`, `T2.1-ridge-lags` (+ corrected `T1.2-baseline-validation-mdafix`) in runs.jsonl

## What was done

Three baselines beyond persistence were implemented in
`prediction/experiments/baselines_suite.py` and run through
`harness.evaluate()` on the identical 5 expanding folds (val windows
2008–09 … 2016–17, anchor 2017). Persistence is computed by the harness itself
on the same folds and same row masks as each model (`_score_fold` common-mask),
so every model-vs-persistence number below is paired within-fold.

All baselines forecast the **`total` index level** directly — that is what the
harness scores; the Δlog-vs-level question is studied separately in T2.2.

1. **Drift (random walk with drift):** per CMA, drift = mean first difference
   of the level over the fold's train window; `y(t) = y_last + h·drift`,
   h = months since the CMA's last train observation.
2. **Per-CMA ARIMA:** statsmodels `ARIMA(order=(1,1,0))`, fit per CMA on the
   train window only (~90 fits total, seconds of compute). Fixed small order
   chosen a priori to bound compute (no pmdarima installed; no search).
3. **Ridge-on-lags:** ONE pooled `Ridge(alpha=1.0)` across all CMAs on all 176
   existing `*_lag_1` features from `X_train_full_total.csv` plus CMA dummy
   columns, standardized by a `StandardScaler` inside an sklearn Pipeline fit
   on the train window only. Pooled-with-dummies chosen over per-CMA because
   early folds give each CMA only ~270 monthly rows against 176 features;
   whether spatial pooling truly helps is probed properly in T2.3.
   Late-starter CMAs unseen at train time are scored via dummy reindex(fill=0)
   using numeric lags alone (fold-5 eval rows = 317 for ridge vs 245 for
   drift/ARIMA, which cannot produce any prediction for those CMAs).

## Verdict: the bar

**Persistence wins every metric against every challenger.** Margins:

- vs drift: MDA +0.042 absolute (+10% relative); point errors ~48× smaller
  (NRMSE 0.00113 vs 0.00704).
- vs ARIMA(1,1,0): MDA +0.028 (+6.5% relative); point errors ~7× smaller.
- vs ridge-on-lags: MDA +0.091 (+25% relative); point errors ~1.5× smaller
  (NRMSE 0.00113 vs 0.00166, NMAE 0.00061 vs 0.00119).

Interpretation:

1. NHPI `total` is close to a martingale at monthly frequency: estimated drift
   and AR dynamics extrapolated over up-to-24-month horizons actively hurt
   (they accumulate error in trends that reverse). ARIMA's slight edge on
   fold-2/5 MDA does not survive aggregation.
2. Ridge-on-lags is the only challenger in persistence's error class on point
   metrics — pooled lag features carry real level information — but its
   directions are WORSE than chance-flavored (MDA 0.371 < 0.4625): smoothing
   across CMAs/quarters mispredicts month-to-month sign more often than
   copying yesterday does. Directional skill must come from somewhere else
   (target reformulation or genuinely different signal), which motivates T2.2.
3. Downstream definition: "beating the baseline" = beating **persistence**
   (MDA 0.4625±0.0394, NMSE 1.52e-06±1.27e-06, NRMSE 0.00113±0.00049,
   NMAE 0.00061±0.00024) on the same folds/masks. No simple time-series
   baseline comes close on direction.

## Pitfalls encountered

- First suite attempt crashed in the ARIMA predictor (positional-vs-label
  indexing of months); fixed with an index-aligned month Series. The crash
  left one duplicate `T2.1-drift` row in runs.jsonl; since the registry row is
  byte-equivalent to its re-run (deterministic harness) and the artifact had
  been overwritten, the earlier duplicate was removed rather than kept —
  documented here instead of silently ignored.
- Drift/ARIMA cannot predict CMAs with no train history, so their fold-5
  evaluation set shrinks to 245 rows while ridge/persistence score 317; the
  leaderboard reports `fold5_eval_rows` explicitly and each run carries its
  own same-mask persistence block for fair paired comparison.
- statsmodels convergence warnings on short series suppressed inside the
  fitting context only; fits verified finite via downstream assertions.
