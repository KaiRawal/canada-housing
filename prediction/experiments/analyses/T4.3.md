### 2. New experiment — recursive vs direct vs classical

**Folds & features exactly as T4.1/4.2**: 5 expanding 2-year folds 2008-09 … 2016-17 (train rows 5624→7352, 18 CMAs folds 1-4, 24 in fold 5; val windows 24 months each = 432 rows folds 1-4, 323/317 rows fold 5 depending on CMA availability — documented per-fold in `*_results.json`). Feature sets pruned to A/B only (per 2026-08-28): `A_base_lag1` (176 lag-1 cols), `B_base_lag1_own_sub` (A + 4 OWN-subset: `tot_d12`, `tot_lag12`, `tot_lag24`, `tot_dlog1`). C/k5 and SCSS/RMS already proven C≈B and dropped.

**Inner-CV discipline identical**: expanding time-ordered blocks WITHIN each outer train window ONLY (4×12m), no shuffle. Winning pipeline refit on full outer train window. Implemented via manual loop (clone + sequential fits) to avoid joblib deadlocks.

**Recursive framing**: `skforecast` is not installed in this environment (checked `import skforecast` → `ModuleNotFoundError`; `versions.skforecast = not_installed_fallback_manual_recursion`). Manual recursion fallback used and documented: train 1-step pooled LightGBM (and Ridge) on train window with actual features, then forecast 24 months iteratively per CMA — OWN-subset features `lag12/24`, `d12`, `dlog1` are recomputed from the *predicted* history (causal recursion: `lag12 = hist[-12]`, `d12 = hist[-1]-hist[-13]`, `dlog1 = log(hist[-1])-log(hist[-2])`, 0 fallback when insufficient history), while the 176 covariate lag-1 columns use the observed val row's actual lag-1 covariate (isolates target-memory recursion effect; future covariate values beyond horizon not needed because they are lag-1). For A (no OWN) recursion is a no-op → predictions identical to direct (verified bit-identical).

**Classical**: per-CMA `SARIMAX(1,1,0)` (statsmodels, `enforce_stationarity=False`) fit on train window only per CMA (≥10 obs required), h-step forecast where h = n val rows for that CMA in the fold (24 for full-history CMAs). Pooled `VAR(1)` attempted on the wide month×CMA target panel (train months only, `pivot` + `ffill/bfill`, require n_obs > n_vars); graceful fallback to NaN predictions if infeasible — it **did** fit in this run (wide panel 197 months × 18 CMAs, VAR(1) succeeded; forecast mapped back via Period index). Both classical models are fit per-fold train window only, never seeing val.

**Scoring**: all models through `harness.evaluate` (or equivalent `_score_fold` recursion path) on identical canonical folds/rows; persistence scored alongside on identical masks. Paired intersection-mask deltas are approximated by agg differences (model vs persistence/B-enet) — per-fold `paired_deltas.json` not regenerated because recursive predictions are already on the same mask as direct; the “recursive vs direct” delta is simply the difference of their agg means (A: 0, B: see table).

## Interpretation

1. **Recursion does not unlock directional skill beyond the direct linear/GBM ceiling.** The best recursive model (recursive-LGBM-B, 0.5942) still trails persistence by 0.083 MDA and nominally trails B-enet by 0.004, with worse point errors. The observed +0.017 MDA lift of recursive over direct LGBM-B is within noise (0.038 std) and is direction-only — point errors do not improve. For the canonical B-enet winner (0.5981), recursion is not applicable (linear direct already uses actual lag history); recursive GBM does not surpass it.

2. **Near-martingale panel quantifies remaining headroom.** Even the per-CMA SARIMAX(1,1,0) — a pure time-series model that *should* excel at 1..24-step recursion — only ties persistence directionally and loses badly on point errors (NRMSE 0.00785 vs 0.00113). This confirms the T4.1/4.2 verdict: monthly NHPI `total` has ~40% flat directions and is near-martingale; multi-step iteration accumulates error without gaining direction.

3. **Classical models fail the multi-metric bar.** SARIMAX's nominal MDA proximity to persistence (+0.070 vs B-enet direction) comes with 7× point-error blow-up; VAR(1) is worse on both. They do not provide a headroom path for T4.4 leaderboard — direct B-enet remains the T4 frontrunner for the final model.

4. **Pruned scope validated.** A/B only (B = A + OWN-subset) was sufficient — C/k5 already C≈B, and recursion on A is provably no-op. No SCSS/RMS needed.

## Pitfalls encountered

- **VAR feasibility**: pooled VAR on 18 CMAs × ~197 months is borderline (n_obs > n_vars+lag); `ffill/bfill` for late-starter gaps was required; without it VAR fails with `LinAlgError`. Documented as "gracefully fails on short panel" but in this run it succeeded — still uncompetitive.
- **Fold-5 val row count**: 323 vs 317 in T4.2 is not a bug — it reflects the wide panel's month×CMA availability for 2016-17 (24 CMAs, some with partial histories); direct-LGBM / recursive paths use identical masks, so comparison remains apples-to-apples. Per-fold `n_eval_rows` and `n_mda_directions` are in the saved JSONs.
- **Covariate lag-1 handling in recursion**: full recursion would require forecasting covariates too; we isolate the effect to target-memory (OWN-subset) by using observed covariate lags for val months — explicit caveat in `decision_rule.json`.
